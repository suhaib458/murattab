# إشعارات الجهاز

تعمل إشعارات «مرتب» عبر Web Push. يوافق المستخدم مرة واحدة على كل جهاز، ثم يخزّن الخادم اشتراك الجهاز والتذكيرات المطلوبة فقط. لا يُخزَّن اسم الطالب أو رقمه الجامعي أو ملفه الأكاديمي.

## البنية

- المتصفح ينشئ رمز جهاز عشوائيًا واشتراك Push محميًا.
- واجهات `/api/push/*` تتحقق من رمز الجهاز وتتواصل مع Supabase من الخادم فقط.
- Supabase يحفظ الأجهزة والتذكيرات مع RLS ومن دون صلاحيات مباشرة لـ `anon` أو `authenticated`.
- Supabase Vault يحتفظ بسر استدعاء الـ dispatcher، بينما تحفظ قاعدة البيانات بصمة SHA-256 فقط للتحقق منه.
- Supabase Cron يستدعي `/api/push/dispatch` كل دقيقة.
- عامل الخدمة `public/sw.js` يعرض الإشعار ويفتح صفحة الجدول عند الضغط عليه.
- مفتاح Supabase السري يبقى على Vercel فقط ولا يصل إلى المتصفح.

## متغيرات Vercel

يلزم في Vercel:

```text
SUPABASE_URL=
SUPABASE_SERVICE_ROLE_KEY=
VAPID_PUBLIC_KEY=
VAPID_PRIVATE_KEY=
```

`VAPID_SUBJECT` اختياري. على Vercel يتم اشتقاقه تلقائيًا من رابط المشروع الإنتاجي.

لا يوجد متغير `PUSH_DISPATCH_SECRET` على Vercel؛ سر الـCron يتولد داخل Supabase Vault ولا يغادر قاعدة البيانات.

## قاعدة البيانات

المهاجرتان المطلوبتان:

- `202609210001_push_notifications.sql`
- `202609210002_push_dispatch_security.sql`

قاعدة الإنتاج تحتاج أيضًا إعدادًا تشغيليًا مرة واحدة لإنشاء سر Vault وجدولة `murattab-push-dispatch`. لا يجب حفظ قيمة السر في Git أو في ملفات البيئة.

## ملاحظات الأجهزة

- Android وChrome وEdge وFirefox: يعمل بعد موافقة المستخدم.
- iPhone/iPad: يلزم iOS/iPadOS 16.4 أو أحدث، وتثبيت «مرتب» على الشاشة الرئيسية، ثم تفعيل الإشعارات من داخل التطبيق.
- لا يمكن لأي موقع تفعيل إشعارات الجهاز من دون موافقة المستخدم؛ هذا قيد أمان من نظام التشغيل.
